Model validation is the process of evaluating how well a predictive model performs when applied to new, unseen data. It helps assess the reliability, robustness, and generalizability of the model’s predictions beyond the training dataset.

There are two main types of validation:

  • Apparent validation: Evaluates model performance on the same data used to fit the model. It often overestimates performance.
  • Internal validation: Uses resampling techniques (e.g., cross-validation, bootstrap) to estimate performance while correcting for optimism.
  • External validation: Tests the model on an independent dataset to assess transportability.

1) Apparent Validation

Apparent validation in lrm refers to evaluating model performance on the same data used to fit the model.

print(model4)

predicted <- predict(model4, newdata = df, type = "fitted")
predicted <- pmin(pmax(predicted, 1e-6), 1 - 1e-6)
observed <- as.numeric(as.character(df$y))

calibration_model <- glm(
  y ~ qlogis(predicted),
  data = df,
  family = binomial
)

apparent_metrics <- data.frame(
  AUC = as.numeric(pROC::auc(pROC::roc(df$y, predicted, quiet = TRUE))),
  Brier_score = mean((observed - predicted)^2),
  Calibration_intercept = coef(calibration_model)[1],
  Calibration_slope = coef(calibration_model)[2],

2) Bootstrap Validation

Bootstrap validation involves repeatedly sampling with replacement from the original dataset, fitting the model on each sample, and evaluating it on the “left-out” data.

validate(model4, "boot",50)

4) Cross-validation as a general family

Cross-validation is a family of internal validation methods. In every design, the model is fitted on a training subset and evaluated on observations held out from that fit. The code below explicitly sets method = "crossvalidation" and uses B = 5, so here it represents one 5-fold cross-validation run. The usual term is “folds,” not clusters. Note that validate() defaults to bootstrap validation; B = 5 means five folds only because the method has been set to cross-validation.

validate(model4, "crossvalidation", B = 5)

In this call, B = 5 means that the data are divided into 5 omitted groups. Each fitted model uses 4 folds for training and the remaining fold for testing. The later manual example also uses 5 folds to show the mechanics and calculate custom metrics; it is the same validation principle with a different implementation. This is not five separate repetitions of 5-fold cross-validation.

In practice, rms::validate() is convenient when the model is an rms model and you want a compact, standardized summary. A manual loop is more flexible: it lets you choose custom metrics, keep out-of-fold predictions, and insert preprocessing or modelling steps that validate() does not provide directly. The manual approach is also easier to inspect step by step, but it requires more code and more care to avoid data leakage or incorrect metric calculations. Even with 5 folds in both examples, the results need not match because the examples use different model-fitting functions and metrics.

5) Manual 5-fold Cross-validation

K-fold cross-validation is one specific design within the broader cross-validation family. The code below manually implements 5-fold cross-validation.

set.seed(2025)
k <- 5
fold_id <- sample(rep(seq_len(k), length.out = nrow(df)))

cv_results <- lapply(seq_len(k), function(i) {
  train_data <- df[fold_id != i, ]
  test_data <- df[fold_id == i, ]
  fit <- glm(y ~ x1 + x2 + x3 + x4 + x5,
             data = train_data,
             family = binomial)
  prob <- predict(fit, newdata = test_data, type = "response")
  pred <- factor(ifelse(prob >= 0.5, 1, 0), levels = levels(test_data$y))
  tab <- table(test_data$y, pred)
  observed_agreement <- sum(diag(tab)) / sum(tab)
  expected_agreement <- sum(rowSums(tab) * colSums(tab)) / sum(tab)^2
  data.frame(
    accuracy = observed_agreement,
    kappa = (observed_agreement - expected_agreement) /
      (1 - expected_agreement),
    auc = as.numeric(pROC::auc(pROC::roc(test_data$y, prob, quiet = TRUE)))
  )
})

cv_results <- do.call(rbind, cv_results)
cv_results
colMeans(cv_results)

  • What happens if K is too small? Too large?

6) Internal vs. External Validation

External validation tests the model on a completely independent dataset that was not used at all during model development.

set.seed(123)

logit <- function(x){log(x/(1-x))}
expit <- function(x){exp(x)/(1+exp(x))}

# Simulate a dataset. This is simulated transportability validation,
# not validation in an independent real-world cohort.
n <- 300

x1 <- rnorm(n)
x2 <- rnorm(n)
x3 <- rbinom(n, 1, prob = 0.35)
x4 <- rbinom(n, 1, prob = 0.5)
x5 <- sample(1:4, size = n, replace = TRUE, prob = c(0.3, 0.3, 0.2, 0.2))

logit.py <- -2 + x1 + 0.2 * x1^2 + 0.3 * x2 + 0.1 * x2^2 +
  0.2 * (x3 == 1) + 0.2 * (x4 == 1) + 0.2 * (x5 == 2) -
  0.1 * (x5 == 3) + 0.2 * (x5 == 4) + rnorm(n, 0, 0.1)


py <- expit(logit.py)
y <- rbinom(n,1,py)

df_test_external <- data.frame(y = factor(y), x1, x2, x3 = factor(x3), x4 = factor(x4), x5 = factor(x5))
pred_probs_external <- predict(model4, newdata = df_test_external, type = "fitted")
auc(roc(df_test_external$y, pred_probs_external))
