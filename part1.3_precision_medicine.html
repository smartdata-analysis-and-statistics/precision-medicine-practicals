Model Validation

Model validation is the process of evaluating how well a predictive model performs when applied to new, unseen data. It helps assess the reliability, robustness, and generalizability of the model’s predictions beyond the training dataset.

There are two main types of validation:

  • Apparent validation: Evaluates model performance on the same data used to fit the model. It often overestimates performance.
  • Internal validation: Uses resampling techniques (e.g., cross-validation, bootstrap) to estimate performance while correcting for optimism.
  • External validation: Tests the model on an independent dataset to assess transportability.

The split-sample method is internal validation because both training and testing use the development dataset. It does not provide external validation, and it does not automatically correct optimism. Its test estimate can be unstable because it depends on one random split.

Cross-validation is the general family: each fitted model is tested on observations that were not used for that fit. The exact train/test arrangement depends on the named design. K-fold cross-validation is one specific member of this family, using K - 1 folds for training and 1 held-out fold for testing, repeated until every fold has been used for testing. Therefore, K-fold CV should not be presented as an alternative to cross-validation; it is an example of cross-validation.

The practical implication is that apparent validation is useful for describing the fitted model, bootstrap and cross-validation estimate internal generalizability, and external validation provides the strongest test of transportability.

The metrics and calibration plot above are apparent, in-sample estimates. Because the model is evaluated on the same observations used for fitting, these estimates are expected to be optimistic and should be compared with the bootstrap results below.

Apparent validation evaluates model performance using the same data it was trained on. This might seem convenient, but it’s overly optimistic and misleading for several reasons:

  1. The model may learn patterns that are specific to the training data (noise), and these won’t generalize. Apparent validation can’t detect this.
  2. Accuracy, AUC, and R² often appear much higher than they really are — because the model is tested on data it has already “seen.”
  3. Relying on apparent validation may lead to deploying models that fail when exposed to new data.
TipQuestions for discussion and answers

Question 1. Which metrics are reported in apparent validation?

Answer. This section reports AUC, Brier score, calibration intercept, calibration slope, and pseudo-R², together with an apparent calibration plot.

Question 2. Why are apparent estimates optimistic?

Answer. The model is evaluated on the same observations used to estimate its coefficients, so it benefits from patterns and random noise already seen during fitting.

Question 3. How does overfitting affect apparent validation?

Answer. Overfitting generally makes apparent discrimination and pseudo-R² too high and can make calibration look better than it will be in new patients.

Question 4. Can a model be trusted only because it performs well on the training data?

Answer. No. Good training-data performance is necessary but not sufficient evidence of generalizability; internal or external validation is needed.

Question 5. When is apparent validation acceptable?

Answer. It is useful for describing the fitted model and teaching diagnostics, but it should not be the primary evidence for deployment or clinical performance claims.

2) Bootstrap Validation

Bootstrap validation involves repeatedly sampling with replacement from the original dataset, fitting the model on each sample, and evaluating it on the “left-out” data.

How it works:

  • Create “bootstrap samples” (e.g., 200 samples of the same size as the original dataset).
  • Fit the model on each bootstrap sample.
  • Evaluate the model on the data not included in that sample (called “out-of-bag”).
  • Measure the optimism in performance (e.g., AUC, R²), and subtract it from the original score.
validate(model4, "boot",50)
cal <- calibrate(model4, B = 200)
plot(cal, xlab = "Predicted Probability", ylab = "Observed Probability")
  • AUC (approx from Dxy/2) ≈ 0.613 + 0.5 = 0.8065, R² = 0.305 → slight optimism corrected.
  • Calibration slope drops to 0.869 → indicates some overfitting.
  • Intercept shifts to -0.109 → tendency to overpredict risk.
  • Emax = 0.051 → modest miscalibration at some points.
TipQuestions for discussion and answers

Question 1. What does bootstrap validation correct?

Answer. It estimates optimism caused by fitting and evaluating the model in the same sample, then adjusts performance estimates toward what is expected in new but similar samples.

Question 2. What is optimism, and how is it estimated?

Answer. Optimism is the difference between performance on a bootstrap sample and performance when that bootstrap-fitted model is applied to the original data. Repeating this process estimates the average optimism.

Question 3. Why can bootstrap validation be preferable to a single split in a small dataset?

Answer. Bootstrap uses repeated resamples and retains information from the full dataset, whereas a single split discards part of the data for fitting and can produce an unstable result.

Question 4. How should the calibration slope and intercept be interpreted?

Answer. A slope near 1 indicates appropriate spread of predictions and a slope below 1 suggests overfitting. An intercept near 0 indicates good overall calibration; the negative intercept here is consistent with some overprediction of risk.

3) Split-sample Validation

Randomly split the dataset into training and testing subsets. In this practical, we use 70% of the data for training and 30% for testing.

set.seed(2025)
train_size <- 0.7
train_id <- sample(seq_len(nrow(df)), size = floor(train_size * nrow(df)))
df_train <- df[train_id, ]
df_test <- df[-train_id, ]
train_model <- lrm(y ~ x1 + x2 + x3 + x4 + x5, 
                   data = df_train, x = TRUE, y = TRUE)

Do prediction on new data.

pred_probs <- predict(train_model, newdata = df_test, type = "fitted")
auc(roc(df_test$y, pred_probs))
Area under the curve: 0.7081
  • AUC = 0.8326, close to apparent → may be unstable due to small sample size. The model correctly ranks pairs of cases 83.26% of the time.
TipQuestions for discussion and answers

Question 1. What are the risks of split-sample validation with a small dataset?

Answer. The training model has fewer observations and the test estimate is based on only a subset, so both the fitted coefficients and the AUC can vary considerably with the random split.

Question 2. How should test performance be compared with training performance?

Answer. Test performance should generally be lower or less precise than apparent training performance. A similar value in one split is not proof of generalizability because the split may be favorable and the estimate is noisy.

4) Cross-validation as a general family

Cross-validation is a family of internal validation methods. The common principle is to repeatedly fit the model on a training subset and evaluate it on a corresponding held-out subset. The exact scheme must be named: the code below uses method = "crossvalidation" and B = 5, so in this practical it represents one 5-fold cross-validation run. Here, “folds” is the usual term; these are not clusters used in cluster analysis.

This is different from the default call to validate(): validate() defaults to method = "boot", which performs bootstrap validation. For method = "crossvalidation", B = 5 means that the development sample is divided into 5 groups; it does not mean five separate repetitions of 5-fold cross-validation.

How the 5-fold example works:

  • Divide the data into 5 subsets.
  • In each round, use 4 folds for training and 1 fold for validation.
  • Rotate so each fold is used as validation once.
  • Average the results across the 5 held-out folds.
set.seed(2025)
validate(model4, "crossvalidation", B = 5)
  • Corrected Dxy is approximately 0.595, corresponding to an AUC of approximately 0.798.
  • Corrected pseudo-R² is approximately 0.297; it should not be interpreted as 29.7% of the outcome variance explained.
  • Corrected calibration slope is approximately 0.941, the intercept is approximately −0.079, and Emax is approximately 0.152.
TipQuestions for discussion and answers

Question 1. Why is cross-validation more reliable than apparent validation?

Answer. Each observation is evaluated in a held-out fold that was not used to fit its prediction, so the estimate is less optimistic than an in-sample estimate. In this example, that means 5-fold cross-validation.

Question 2. What happens if there are too few or too many folds?

Answer. Too few folds can make the training sets substantially smaller and increase bias; too many folds make the estimates more correlated and can increase computational cost and variance. The choice should reflect sample size and the modelling goal.

5) Manual 5-fold Cross-validation

This section implements the same cross-validation principle manually. It uses 5-fold cross-validation, which is a specific design within the broader cross-validation family described above.

The difference from the rms::validate example is therefore implementation: validate() provides a packaged resampling summary for an rms model, whereas this loop exposes each train/test split and lets us calculate accuracy, kappa, and AUC ourselves.

Example (5-fold CV):

  • Data is split into 5 parts (folds).
  • Train on 4 folds, validate on 1 fold.
  • Repeat this process 5 times so each fold is used once for validation.
set.seed(2025)
k <- 5
fold_id <- sample(rep(seq_len(k), length.out = nrow(df)))

cv_results <- lapply(seq_len(k), function(i) {
  train_data <- df[fold_id != i, ]
  test_data <- df[fold_id == i, ]
  fit <- glm(y ~ x1 + x2 + x3 + x4 + x5,
             data = train_data,
             family = binomial)
  prob <- predict(fit, newdata = test_data, type = "response")
  pred <- factor(ifelse(prob >= 0.5, 1, 0), levels = levels(test_data$y))
  tab <- table(test_data$y, pred)
  observed_agreement <- sum(diag(tab)) / sum(tab)
  expected_agreement <- sum(rowSums(tab) * colSums(tab)) / sum(tab)^2
  data.frame(
    accuracy = observed_agreement,
    kappa = (observed_agreement - expected_agreement) /
      (1 - expected_agreement),
    auc = as.numeric(pROC::auc(pROC::roc(test_data$y, prob, quiet = TRUE)))
  )
})

cv_results <- do.call(rbind, cv_results)

NoteWhat is different from the general cross-validation example?

Both examples use the same 5-fold cross-validation principle: each model is trained on 4 folds and tested on the remaining fold. The difference is how the procedure is implemented and summarized.

  • validate(model4, "crossvalidation", B = 5) automatically refits the lrm model and returns model-specific indexes such as Dxy, pseudo-R², calibration slope, intercept, and Emax, including an optimism-corrected index.
  • This manual loop explicitly creates the five train/test splits, fits a glm model in each loop, and calculates accuracy, Cohen’s kappa, and AUC. It is therefore easier to inspect and customize, but it requires more code and careful checks for data leakage and correct metric calculation.

The results are not expected to be identical here because the examples use different model-fitting functions and different metrics. A numerical comparison would require the same fold assignments, the same model-fitting function, and the same performance metrics in both implementations.

TipQuestions for discussion and answers

Question 1. What does K represent?

Answer. K is the number of folds. With K = 5, the model is trained on four-fifths of the data and evaluated on the remaining fifth, with every fold used once for testing.

Question 2. What happens if K is too small or too large?

Answer. A small K leaves less data for training and can increase bias; a very large K can increase variance and computational cost. The folds must also be large enough to contain both outcome classes.

Question 3. How does this improve the performance estimate?

Answer. It produces out-of-fold predictions for all observations and averages performance across several splits, reducing dependence on one arbitrary train/test partition. It still estimates internal, not external, validity.

6) Internal vs. External Validation

External validation tests the model on a completely independent dataset that was not used during model development. The example below is simulated transportability validation, not validation in an independent real-world cohort.

set.seed(123)

logit <- function(x){log(x/(1-x))}
expit <- function(x){exp(x)/(1+exp(x))}

# Simulate a dataset. This is simulated transportability validation,
# not validation in an independent real-world cohort.
n <- 300

x1 <- rnorm(n)
x2 <- rnorm(n)
x3 <- rbinom(n, 1, prob = 0.35)
x4 <- rbinom(n, 1, prob = 0.5)
x5 <- sample(1:4, size = n, replace = TRUE, prob = c(0.3, 0.3, 0.2, 0.2))

logit.py <- -2 + x1 + 0.2 * x1^2 + 0.3 * x2 + 0.1 * x2^2 +
  0.2 * (x3 == 1) + 0.2 * (x4 == 1) + 0.2 * (x5 == 2) -
  0.1 * (x5 == 3) + 0.2 * (x5 == 4) + rnorm(n, 0, 0.1)


py <- expit(logit.py)
y <- rbinom(n,1,py)

df_test_external <- data.frame(y = factor(y), x1, x2, x3 = factor(x3), x4 = factor(x4), x5 = factor(x5))
pred_probs_external <- predict(model4, newdata = df_test_external, type = "fitted")
auc(roc(df_test_external$y, pred_probs_external))
Area under the curve: 0.7684

0.7969 means the model correctly ranks pairs of cases 79.69% of the time.

TipQuestions for discussion and answers

Question 1. Why is external validation considered the strongest test of transportability?

Answer. It evaluates the locked model in an independent patient population that was not used for model development, so it tests performance under a genuinely new case mix and care setting.

Question 2. What would a drop in external performance suggest?

Answer. It could indicate differences in case mix, predictor measurement, outcome prevalence, clinical practice, or model overfitting. Calibration should be inspected as well as AUC.

Question 3. Which validation approach is most appropriate for this dataset of about 200 observations?

Answer. Bootstrap validation and repeated or stratified cross-validation are preferable for internal validation because they use the available sample efficiently. The simulated external example is useful for teaching transportability, but it is not a substitute for validation in a real independent cohort.
